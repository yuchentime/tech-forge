# 知识画像产品讨论稿

**文档状态：** 产品讨论稿，待产品评审  
**讨论对象：** 是否做、为谁做、展示什么、如何判断做对了  
**范围：** 只讨论产品定义、用户价值、信息结构与验收，不涉及实现方案  
**关联能力：** 演练模式、长期记忆、资料库

## 1. 一句话

把历史演练中的作答证据，汇总成教师自己的知识画像，回答两个问题：**我讲到什么程度？下一步练什么？**

## 2. 背景与问题

演练模式已经能产出主题、知识点、逐题评估、总体报告和复习建议。但这些结果只属于那一次演练、那一个课题：

- 用户看得到“这次哪里没讲清”，看不到“跨课题我整体怎么样”。
- 同一个薄弱点可能在不同课题里反复出现，但没有人把它串起来。
- 教师无法判断知识结构短板，演练结论也不会自动影响下一次学习；长期记忆缺少用户可见的出口。
- 产品已有“资料库”管资料、“设置”管配置，缺少一个面向“我”的入口。

### 2.1 待验证假设

| 编号 | 假设 | 验证方式 |
|---|---|---|
| H1 | 完成过演练的教师会关心跨课题的掌握情况 | 访谈 + 入口点击率 |
| H2 | 单次演练报告不足以支撑“下一步学什么”的决定 | 任务测试：只看报告能否说出下一步 |
| H3 | 带证据的结论比一个分数更能建立信任 | 可用性测试 + 纠错率 |
| H4 | 教师愿意花约 1 分钟纠正错误结论 | 纠错入口使用率 |

## 3. 产品定位

**是：**

- 长期记忆中“教师知识状态”的第一个用户可见出口。
- 演练结果的跨课题汇总，不是单次报告的重复展示。
- 下一次学习或演练的起点，形成“学习 → 演练 → 画像 → 再学习/再演练”的闭环。
- 只服务教师本人：单人、本地、不分享、不排名。

**不是：**

- 考试成绩单：没有百分制、等级、排名、证书。
- 知识图谱：当前证据不足以支撑概念之间的因果或依赖关系。
- 学生画像：学生画像描述 AI 扮演的提问对象，知识画像描述教师自己。
- 自动学习计划：画像给建议和入口，不替教师排课。
- 教学风格画像：只回答“知识讲到什么程度”，不评价讲课风格或教学能力。

### 3.1 与现有模块的关系

- **演练：** 唯一证据来源；画像不引入演练之外的能力判断。
- **资料库：** 资料是学习材料，不是掌握证据；未来可提示“有资料但没演练”的覆盖缺口。
- **普通对话与设置：** 对话不是掌握证据，只作为进入学习的入口；设置与本页无关。

## 4. 目标用户与场景

**前提用户：** 至少完成过一次有报告、且作答量足够的演练。从未演练的用户看到引导，而不是空图表。

| 场景 | 用户问题 | 画像要给的答案 |
|---|---|---|
| 演练刚结束 | 这次哪里没讲清？ | 本次知识点状态 + 可下钻的原题原答 |
| 下次备课前 | 我该先补哪块？ | 按优先级排序的薄弱点与复习建议 |
| 积累多个课题后 | 我的知识结构短板在哪？ | 跨主题的重复缺口、覆盖广度、稳定强项 |
| 久未练习 | 之前的结论还作数吗？ | 时效标签与建议复练项 |

## 5. 设计原则

| 编号 | 原则 | 产品含义 |
|---|---|---|
| E1 | 证据优先 | 每个结论都能点回原题、原答和评估依据 |
| E2 | 不制造分数 | 只给状态、证据量和时间，不给百分制或排名 |
| E3 | 未验证不是薄弱 | 跳过、未作答、未覆盖、报告失败都保持“未验证” |
| E4 | 区分误解与遗漏 | “理解错了”需要纠正，“没讲到”需要补学 |
| E5 | 区分独立掌握与提示后掌握 | 两次追问才说清，不能与一次讲清同等看待 |
| E6 | 反馈面向行动且平衡 | 用“下一步练什么”组织；稳定掌握也要被看见 |
| E7 | 时效透明、教师可纠正 | 显示新鲜度，不静默降级；允许“不认同/已复习” |

## 6. 核心概念

| 概念 | 定义 | 产品备注 |
|---|---|---|
| 演练证据 | 一次已提交回答并完成评估的演练回答 | 跳过、未作答不算证据 |
| 主题 | 一次演练覆盖的范围 | 同一主题可能有不同叫法，需要归并 |
| 知识点 | 演练计划中的知识单元 | 一次演练通常 3–8 个 |
| 掌握状态 | 掌握 / 部分掌握 / 薄弱 / 未验证 | 沿用现有演练报告词汇，不另造一套 |
| 证据强度 | 不足 / 有限 / 较充分 | 按该次演练已评估回答数分档，阈值待定 |
| 稳定性与时效 | 稳定/不稳定/待观察；新鲜/建议复练/历史结论 | 同一知识点多次演练是否一致；30 天、90 天为默认分界 |

## 7. 信息架构

**入口：** 侧栏「资料库」下方，与「资料库」同组；点击切换主区域视图，不是弹窗。

| 区块 | 目的 | 内容 | 交互 |
|---|---|---|---|
| 概览 | 先给事实，不给分数 | 已完成演练数、覆盖主题数、已评估回答数、最近演练日期、方法说明 | 无 |
| 主题 | 看单块知识的掌握 | 主题名、演练次数、最近日期、状态分布、知识点列表、证据强度 | 展开知识点；进入主题详情 |
| 反复出现的缺口 | 找跨课题的共性问题 | 出现 ≥2 次的误解/遗漏、频次、最近一次、来源演练 | 查看原题原答；回到来源课题 |
| 稳定掌握 | 确认强项，平衡反馈 | 多次一致、时效新鲜、证据充分的知识点 | 查看证据 |
| 证据不足 | 避免过度解读 | 进行中、报告失败、已评估回答过少的演练 | 继续演练 / 重试结束 |
| 下一步 | 把认知转成行动 | 按“先补薄弱、再复练过期、最后扩展未覆盖”排序的建议 | 回到课题；发起针对性演练（分期） |

**趋势边界：** 同一主题只有 1 次演练时不画趋势，只显示本次结论和“证据有限”；有 2 次及以上时展示每次演练的状态分布，而不是 0–100 的曲线；最近两次结论相差较大时标“不稳定”，不做平均。

## 8. 页面状态

| 状态 | 用户看到什么 | 不能做什么 |
|---|---|---|
| 0 次完成演练 | 说明画像的价值和证据规则，给“开始演练”入口 | 不画空图、不造假数据 |
| 1 次演练 | 本次知识点状态 + 证据下钻；标注“仅 1 次演练” | 不展示趋势、不提示“反复出现” |
| 多次演练 | 主题趋势、跨主题缺口、稳定掌握 | 不把不同学生画像下的难度直接比较 |
| 有进行中演练 | 顶部提示“继续未完成的演练” | 不把进行中数据计入掌握 |
| 报告失败 | 列入“证据不足/未完成”，保留逐题数据入口 | 不生成掌握结论 |
| 来源课题被删除 | 对应证据消失，画像重算 | 不保留幽灵结论 |

## 9. 命名

| 候选 | 优点 | 问题 |
|---|---|---|
| **知识画像** | 准确覆盖“知识结构 + 掌握情况”；与学生画像不撞词；4 个字，侧栏放得下 | 略抽象，需要副标题解释 |
| 我的画像 | 贴近用户原话 | 产品里“画像”已指学生人设，容易被理解成“编辑学生画像” |
| 掌握度 | 直白 | 像成绩单，容易诱导打分和比较 |
| 知识地图 | 形象 | 当前没有概念关系，属于虚假承诺 |

**建议：** 侧栏用「知识画像」，页标题用「我的知识画像」，副标题说明证据来源。若坚持「我的画像」，页内必须与学生画像明确区分。

## 10. 范围与分期

### v1（建议先验证）

- 跨课题汇总已完成演练的结论。
- 主题 → 知识点两层结构；同一主题按名称归并，保留原始名称可查看。
- 掌握状态、证据强度、时效标签。
- 证据可下钻到来源演练，查看原题、原答与评估依据，并能回到来源课题。
- 0 次 / 1 次 / 多次三态。
- 至少支持“不认同 / 已复习”的纠正入口。

### v2（验证后再做）

- 知识点级证据：能定位到具体哪几道题支撑某个结论。
- 主题与知识点的语义归并、手动合并/拆分；反复缺口去重。
- 从画像直接发起针对性演练，而不是只跳回原课题。
- 覆盖建议：结合资料库提示“有资料但从未演练”的主题。

### 明确不做

- 百分制、等级、排名、证书、跨用户比较。
- 知识图谱或概念关系图。
- 自动生成学习计划或课程表。
- 教学风格、课堂表现、学生反馈画像。
- 导出、分享、云端同步。

## 11. 验收与指标

**定性验收：**

- 用户能在 30 秒内说出“我最该补的是什么”。
- 随机抽查结论，能点回原题、原答和评估依据。
- 用户能纠正错误结论，纠正后汇总结果随之变化。
- 用户不会把“未验证”误读为“薄弱”。

**待验证指标（假设，不是承诺）：**

- 完成演练后 7 天内访问画像、并在查看后发起演练或回到课题的比例：判断需求与行动闭环。
- 纠正率与主题手动合并次数：判断评估可信度和自动归并是否够用。

## 12. 风险与讨论点

| 风险 | 表现 | 产品对策 |
|---|---|---|
| 样本太少 | 一次演练就下结论 | 证据分级；未验证单列；1 次演练不画趋势 |
| 名称不统一 | “消息队列”和“MQ”被当成两个主题 | 显示原始名称；允许纠正；v2 做语义归并 |
| 学生画像不同 | 提问难度不同，结论不可直接比较 | 标注提问视角；不跨画像做排名 |
| 删除课题 | 证据消失，结论跳变 | 重算并说明来源；不保留幽灵数据 |
| 反馈伤人 | 画像变成“缺陷清单” | 以“下一步”组织；并列展示稳定掌握 |
| 纠错成本高 | 用户不信任但懒得改 | 一键“不认同/已复习”；记录原因可选 |
| 变成第二份报告 | 没有跨课题增量 | 强化趋势、重复缺口、覆盖广度 |
| 边界被误解 | 把讲稿/资料/聊天当成掌握证据，或把“讲得出”当成“会教学” | 明确只有演练作答算证据；说明能力边界，不评价课堂表现 |

## 13. 待决问题

1. **命名**：用「知识画像」，还是保留「我的画像」并接受与学生画像的区分成本？
2. **v1 是否包含纠正**：如果第一版只能看不能改，错误结论会不会直接破坏信任？
3. **v1 是否允许手动合并主题**：自动归并出错时，用户能否当场修正？
4. **证据阈值**：已评估回答少于 3 条标“证据不足”、3–7 条标“有限”、8 条以上标“较充分”，是否接受？
5. **时效阈值**：30 天提示复练、90 天标“历史结论”，是否符合教师的知识更新节奏？
6. **是否展示“稳定掌握”**：正向反馈是必要的平衡，还是会让页面变长？
7. **“从画像发起演练”放 v1 还是 v2**：不放，闭环就断在“回到课题”；放，范围会明显变大。
8. **首要成功指标**：入口访问率、行动转化率、纠错率，哪一个最能证明这个功能值得做？
