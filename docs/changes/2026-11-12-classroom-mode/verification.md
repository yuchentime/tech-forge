## 2. 实机（Windows 11，125% 缩放，屏幕 2560×1440 物理）

运行方式：`npm run dev:desktop` 的等价链（Vite 5173 + Electron 带 `--remote-debugging-port`），用 CDP 读取渲染层视口并按坐标拖动窗口边缘。

| 检查 | 观察 |
|---|---|
| 入口位置 | 侧栏文本顺序：新建课题 / 资料库 / 知识掌握 / **课堂模式** / 会话列表 / 设置 |
| 进入后窗口比例 | 内容区 1408×792（1.77778）、1675×942（1.77813）、1756×988（1.77733）三次进入均为 16:9；窗口外框 1424×830（比例本就非 16:9，符合「约束内容区」） |
| 舞台铺满 | `.tf-classroom-stage` 边界等于视口 `[0,0,1399,787]` / `[0,0,1756,988]`，无留边、无裁剪；截图可见教室图铺满、左上「退出课堂模式」与右上「课堂模式」胶囊 |
| 拖右边缘 96px | 窗口 1430×834 → 1513×881；内容区 1500×844（1.7773），宽度主导 |
| 拖右边缘 72px | 窗口 1690×979 → 1762×1022；内容区 1748×984（1.7764） |
| 拖下边缘 48px | 窗口 1513×881 → 1599×930；内容区 1586×892（1.7780），高度主导且宽度按比例跟随 |
| 退出（无缩放） | 窗口回到进入前 1686×976；聊天视图与侧栏恢复 |
| 退出（模式内缩放过） | 保持用户尺寸 1762×1022，不回跳 |
| 退出后自由缩放 | 拖右边缘 64px：窗口 1599×930 → 1663×930，内容区 1650×892（1.8498），比例锁已解除 |
| `Esc` 退出 | 与按钮一致：聊天视图恢复、窗口还原 |
| 最大化时进入 | 先还原普通窗口再锁比例：内容区 2048×1082（最大化）→ 1756×988（1.77733），舞台铺满 |
| 最大化窗口内舞台 | 不进入（最大化时无法锁比例）的旧截图显示 `.tf-classroom-stage` 为 1923×1082 居中、左右各 63px `ink-900` 留边，属于预期的降级表现 |

## 3. 被否方案的实际证据

| 方案 | 实测 |
|---|---|
| `win.setAspectRatio(16/9)` | 窗口 1643×924（1.7774）→ 内容区 1630×887（1.8377），舞台 `[26,0,1577,887]` 出现 26px 侧边留边 |
| `win.setAspectRatio(16/9, {frame})` | 窗口 1653×930（1.7774）→ 内容区 1639×892（1.8374），同样偏宽；`extraSize` 未生效 |

## 4. 已知行为

- React 开发模式（StrictMode）下挂载/卸载各执行一次，日志可见 `enter → exit → enter`；生产构建只执行一次。几何结果不受影响。
- 不写自动化测试覆盖 `will-resize`（需要真实窗口与指针拖动）；几何纯函数由单测覆盖，交互行为由上述实机记录覆盖。
