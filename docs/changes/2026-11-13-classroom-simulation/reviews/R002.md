## 3. 结构与可读性评审

### 3.1 做得好的部分

- **分层可讲清**：`lessons`（行 + 文件）、`llm/*`（模型调用）、`classroom`（HTTP 边界）三层职责单一；控制器只做校验、错误映射、委托，没有业务规则。
- **错误词汇表独立成文件**：`lesson.errors.ts` 让「不存在 / 已结束 / 记录损坏」成为可判定的类型，控制器不再猜字符串——这正是 R001 W003 想要的结果。
- **注释在解释「为什么」**：`enqueue()` 的「失败的前驱不得阻塞队列」、桥接「只重试 GET，因为 POST 重放会重复消息与计费」、迁移「先把多余 active 关成历史再建索引」、`endLesson()` 的队列理由，都是决策级注释，不是复述代码。
- **提示词与常量上提**：`STUDENT_ROSTER`/`CLASSROOM_SYSTEM_PROMPT`/两个超时常量都在模块顶部，改规则不用翻方法体。
- **测试粒度按层切分**：`classroom-runtime.test.cjs` 用「永不返回的 fake session」验证超时/取消，不碰网络；`classroom-turns.test.cjs` 用 fake agent 验证锁；`classroom-lessons.test.cjs` 用真 Nest/Fastify 验证 HTTP 契约。三层各测各的，读起来没有猜测成本。
- **`runPiTurn` 的取消竞态写清了代价**：abort 先行、`void run.catch()` 防未处理拒绝、`readAssistantText` 把 provider 拒绝/截断/取消分类成不同错误——这些是硬骨头，注释把陷阱写在代码旁。
